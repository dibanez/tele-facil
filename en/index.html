They just want to watch TV

A forty-button remote, a set-top box that ignores numbers, and an elderly person who just wants to put Telecinco on. This is what it took to get it down to six big buttons.

The scene is more common than it sounds. Someone has been watching television for sixty years, and one day they can no longer turn it on. Not because they have lost anything: because the equipment changed. Where there used to be a dial and two buttons, there is now a set-top box with menus, an app that updates itself, a channel grid you navigate with arrow keys, and a remote with forty keys, four of which matter.

What happens next is always the same. One day something gets pressed by accident, the screen jumps somewhere unfamiliar, and there is no way back. From then on the remote goes untouched. Whatever is on, stays on. And changing the channel means waiting for someone to come round.

The problem is not that they don't understand the technology. It's that the technology doesn't understand what they want it for.

Changing channel is not a task that requires learning a system. It is a gesture. And a gesture that has stopped working is a piece of independence lost — small, daily, and quite humiliating to have to ask for.

What it looks like in the end

The result has no menus, no settings, no home screen. This is all of it: six channels, three volume buttons. One button does one thing. Always the same thing.

What sits behind it

A Raspberry Pi running Home Assistant, on the same network as the set-top box. Home Assistant talks to the box over the same protocol the Google TV remote uses: paired once with a code on the screen, it survives reboots and reconnects on its own. The panel is a Home Assistant screen with the buttons scaled to the size of a thumb.

Button panel→ Home Assistant→ Android TV Remote→ Set-top box→ TV

The seemingly more direct route, ADB, was rejected as the primary path: it requires turning on network debugging in the box, and that switches itself off on reboot on many Android TVs. For a system that lives in someone else's house and cannot be attended to daily, that difference is everything.

And then the box ignored the numbers

The plan was obvious: the remote has a number pad, so to put Telecinco on you send a 5. It doesn't work. On this box — a DIGI R2A — digits go to the firmware of the device, not to the app running on top of it that actually paints live television. Pressing a number does precisely nothing. The channel up and down keys are ignored too. So are the arrows.

The only route that works is the one a person would take: open the channel grid and walk to the one you want. Which raises the real problem underneath all of this: to count positions you have to know where you are counting from, and the television could be anywhere — in the guide, in a menu, on a programme page, in Netflix.

The piece that solved it is an internal link in the app, digitv://channel, which opens the grid with focus always on the first position, wherever the box happened to be. That makes every command absolute rather than relative: it doesn't matter what came before, or whether the previous command was cut off halfway.

Don't ask where you are. Go somewhere you know, and count from there.

With the fixed point found, the rest was measuring against the real hardware. Two traps cost an afternoon each:

  • On the programme page, the Watch now button is already focused. Sending a down arrow before confirming — which seemed like the logical thing — moved focus into the Similar row. The symptom: you asked for Telecinco and got Top Gear.
  • The command that fires the link is cut off after nine seconds and still reports success. The failure was silent: it looked like it worked and quietly ate the last steps. The fix was moving every wait outside the command.

Five decisions that matter more than the code

What makes this something you can leave in a house and forget about is not the YAML. It is this:

  1. A fixed point, not a state

    The system does not remember which channel is on, and does not trust where the interface was left. Every command starts by taking the television somewhere known. A system that corrects itself on every use never accumulates errors.

  2. A double tap can't break anything

    On a touch screen it is trivially easy to tap two channels in a row. If commands queued, the second would wait twenty seconds while the TV visits a channel nobody asked for. Instead, a new command cancels the previous one — and since every sequence starts from the fixed point, cutting one short leaves nothing broken.

  3. If something falls over, it gets back up

    The box reboots, the Wi-Fi blips, the connection drops. Before giving up, the system reloads the integration and waits for it to return. Nobody in that house is going to read an error log.

  4. The wait is stated, not hidden

    Changing channel takes twelve to eighteen seconds, because the grid has to be navigated and there is no shortcut. A panel that says nothing gets pressed three more times. One that says «takes about fifteen seconds» turns the flaw into something tolerable.

  5. Never name the machine

    No Home Assistant, no Raspberry, no integrations, no channel numbers. To the person using it this is not a home automation system: it is the telly. Every visible word has to be theirs.

What about talking to it? Alexa

Voice is the natural next step, and for this case it may beat the panel: no tablet to find, no screen to see clearly, no target to hit with a finger. «Put Telecinco on» is exactly the gesture that was lost.

Technically the work is already done: every button on the panel is a named action, and exposing actions to Alexa is a solved problem. There are two routes, and it is worth knowing what each costs before choosing.

The free route

Emulate a Philips Hue bridge. Home Assistant can pretend to be a bridge full of light bulbs, and Alexa then discovers each channel as if it were a lamp: «Alexa, turn on TV Telecinco». It costs nothing and never leaves the house. The obstacle is mundane: Echo devices only look for Hue bridges on port 80, which in a standard Home Assistant install is already taken by the system itself — and which it reverts on every boot. That is the part still unsolved here.

The paid route

Home Assistant Cloud (Nabu Casa). The official Alexa integration. It works without tricks, it is maintained by the same team that builds Home Assistant, and it solves remote support access without opening ports on the router.

In exchange it is a monthly subscription — on the order of six or seven euros a month, per their pricing page — not a one-off payment. For a domestic setup meant to last years, that fee is the real decision in this project: it isn't expensive, but it is forever.

And there is one detail that catches everyone out the first time: Alexa's native commands always win. «Alexa, turn the volume up» will never reach the television; the Echo applies it to itself. You have to say «turn the telly up». The whole list of phrases has to be written around what Alexa already thinks it knows — and written the way the person would actually say it, not the way it seems logical to you. If they say «put the Telecinco on for me», then that is the phrase, article and all.

That said, voice doesn't always win. Noise from the television itself, a hearing aid, a way of speaking the recogniser doesn't expect: any of those turns voice into a coin toss. Six big buttons never fail. The sensible answer is to have both, with voice as an extra rather than the only way in.

The code is split into three layers, and that separation is the only thing that makes supporting more boxes realistic: one layer knows how the device is reached, another knows how a channel is reached — the model-specific part — and the third knows what the person is asking for. Porting the project to another operator's box means rewriting the middle one and leaving the other two alone.

I suspect the underlying trick will repeat, too: find an action that always leaves the interface in the same place, and count from there. Nearly all of these apps have one.

The technology didn't have to do more. It had to ask for less.
